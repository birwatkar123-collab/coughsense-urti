# COUGHVID reproduction audit

Inspected 2026-09-20. Upstream: https://github.com/Mele0/COUGHVID
Downloaded source and metadata are in `reference/COUGHVID/`; training was not run.

## Conclusion

The repository supports a research prototype, but does not supply everything needed to reproduce its reported results or predict from a new raw cough. No trained model was present in the inspected file tree. The missing audio-to-training-image and label construction steps must be recovered from the author or replaced with an explicitly new pipeline.

## Verified model outputs

`Scripts/Full_Notebook.ipynb` trains an LSTM with a single sigmoid output. Its final evaluation uses probability >= 0.5 for class 1. The plot labels associate class 1 with upper infection and class 0 with no upper infection. Training reads an external `labels_new.csv`, so that file's construction still needs verification.

The notebook saves `probabilities_best_model.npy`, `covPredict_best_model.npy`, fold checkpoints, `best_lstm_model.keras`, embeddings, and evaluation PDFs. It also evaluates a random forest and an average LSTM/random-forest ensemble. These outputs are generated by running training; they are not supplied pretrained assets.

## Missing inputs and inconsistencies

- Notebook paths point to `/kaggle/input/datasss/augmented_spectrograms2/augmented_spectrograms2` and `labels_new.csv`. Neither is supplied.
- README references `cough.ipynb`, which is absent. Supplied preprocessing scripts do not construct the mel-spectrogram training images or document all their rendering parameters.
- Notebook imports `attention_layer_py`, while the supplied module is `attention_layer.py`.
- Notebook resizes images to width 88, height 39, then reshapes them to `(88,39,3)`. The separate hybrid model uses `(39,88,3)`. Reshape is not transpose; these inputs cannot be treated interchangeably.
- Both image loaders divide pixel values by 225.0. Changing to 255.0 changes the model's inputs and cannot be done silently when reusing weights.
- Notebook trains a five-fold LSTM; the standalone script trains a ten-fold attention CNN-LSTM. These are distinct architectures, and neither should automatically be described as the README's reported standalone CNN.
- Standalone script writes `.keras` checkpoints but later loads `.hdf5` paths and hard-codes the best fold.
- The split is over already augmented images, without grouping by original recording. Related augmented samples could cross train/test boundaries. A new pipeline must split source recordings before augmentation, and group by participant where identifiers permit.
- Some reported fold AUC calculations consume thresholded predictions. Evaluate ROC AUC with continuous scores instead.

## Metadata inspection

`metadata_preprocessed.csv` has 3,268 rows but only 2,546 unique UUIDs. Its `diagnosis_upper_infection` values include 0.2, 0.4, 0.6, and 0.8, as well as missing values. This is not a clean binary ground-truth table. Do not convert these values into clinical labels by arbitrary rounding or treat duplicate UUID rows as independent examples.

`metadata_imputed.csv` contains categorical diagnoses, including 895 upper-infection rows, but its name and the described imputation pipeline mean label provenance needs checking against original expert annotations. Neither the user-reported COVID status nor `status_SSL` should be substituted for the URTI target.

## Original ZIP inspection (2026-09-20)

Reproduce using `./inspect_dataset.ps1`. Aggregate results: `dataset_inspection.json`. Recording-level vote counts: `expert_label_audit.csv` (an audit table, not finalized training labels).

- 34,434 metadata rows, 34,434 unique recording UUIDs and 34,434 audio entries. No duplicate audio UUIDs or missing audio matches were found. File contents were not decoded or checked for duplicate audio content, and unique UUIDs do not establish unique participants.
- 2,841 recordings have at least one expert diagnosis; 31,593 do not. Of labeled recordings, 2,711 have only one diagnosis and 130 have multiple diagnoses.
- 729 recordings have only upper-infection votes; 2,014 have only non-upper-infection votes. These counts include singly annotated recordings, not just multi-expert consensus.
- 98 recordings have conflicting URTI-versus-non-URTI votes. There are 124 exact-diagnosis disagreements when differences among non-URTI categories are also counted.
- Excluding binary disagreements leaves 2,743 candidate recordings. Additionally excluding recordings with any expert quality of `poor` or `no_cough` leaves 2,466: 695 upper-infection and 1,771 non-upper-infection. This is a proposed conservative metadata filter, not a validated training cohort; signal quality and labeling policy still need review.
- Expert annotations are cough-based assessments, not independently confirmed clinical outcomes. Do not equate a trained score with a calibrated probability of actual disease.

Next step: use a documented annotation policy to construct source-recording splits and a shared audio preprocessing pipeline. No training, package installation, or audio extraction was performed during this inspection.
